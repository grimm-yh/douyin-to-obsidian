# 笔记模板与排版规范

归纳 `note_draft.md` 时按此执行。目标是**可扫读**，不是信息量最大。

## Frontmatter（固定 6 个字段，不增不减）

```yaml
---
标题: <视频标题>
来源: <原始链接>
作者: <作者>
创建时间: <YYYY-MM-DD>
状态: 待复核
标签:
  - <主题>
---
```

规则：
- 日期字段名是 `创建时间`，不是 `收录` / `captured`
- 不含 `platform`（恒定值无信息量）、不含 `aweme_id`（机器字段）
- 去重靠外部台账（`<vault>/.douyin-processed.json`），不写进笔记
- `状态` 取值：`待复核` → `已复核`
- `标签` 取自视频 hashtag，但**活动标签要删**（如「××知识大赏」这类没有主题信息量）
- `创建时间: 2026-10-25` 会被 YAML 解析成 date 类型，这是期望行为

## 排版规则

1. **标题下用 `>` 引用块放「一句话结论」**，只加粗核心句，不整段加粗
2. **章节用中文序号**：`## 一、问题` / `## 二、方案` / …，每节只讲一件事
3. **对比性信息一律用表格**，不要写成连续 bullet
4. **时间戳不逐条标注**，放在章节标题末尾、用反引号包区间：
   `## 二、方案：……　\`00:14–00:26\``
5. 列表项控制在 30 字内，长解释移到表格或独立段落
6. 结尾保留 `> [!warning] 质量闸门` 块

## 两种内容类型选不同结构

### A. 方法论型（讲观点、讲做法、讲认知）

```markdown
> 一句话结论

## 一、问题        ← 为什么现在的做法不行
## 二、方案        ← 核心做法，配表格
## 三、为什么成立  ← 机制 / 证据 / 失效场景
## 四、落地步骤    ← 有序列表
## 五、可执行动作  ← checkbox
## 六、存疑 / 未验证
## 七、原文摘录
```

### B. 操作型（菜谱、手工、软件操作）

```markdown
> 一句话流程概括

## 一、配方 / 材料   ← 表格：材料 | 分量 | 要点
## 二、预处理        ← 关键状态判据（比克数更重要）
## 三、分阶段操作    ← 表格：阶段 | 温度/信号 | 动作
## 四、收尾
## 五、可执行动作
## 六、存疑 / 未验证
## 七、原文摘录
```

操作型的关键：**抓住「判据」而不是「参数」**。
转写常常丢数字（或数字在硬字幕里），但「手一攥能成团、一捻就散」这种
状态描述一定在语音里 —— 它比克数更可靠，也更实用。

## 时间戳纪律

- 正文不逐条带时间戳（会打断阅读）
- 只在**章节标题末尾**标本节的区间
- 「原文摘录」里每句前带单点时间戳，便于回跳

## 存疑一节必须写

列出所有不确定的地方，至少这三类：

1. 转写错字（并给出推测原意）：「绘画结束」应为「会话结束」
2. 拿不到的信息：画面上的克数、字幕里的文件名
3. 视频本身没讲清的地方：两台电脑同时改同一文件怎么处理

## 质量闸门

```markdown
> [!warning] 质量闸门
> 转写自本地 faster-whisper large-v3（245s 视频 / 48.6s 推理 / 5.0x 实时，155 段）。
> 真人抖音口播字错率约 3–4%，上述「存疑」列出的错字已标注。
> **未经二次复核前不要当作定论引用。**
```

写明来源、性能数据、段数 —— 让将来的自己知道这份笔记的可信度基线。
